新购 VPS 验收与性能测试实操指南

拿到一台新机器后，花 10 分钟确认硬件规格、网络质量与基础安全

第一步：核对基础硬件与磁盘性能

促销页面标注的 CPU 核心数、内存容量与 NVMe 固态硬盘规格，在开通后应第一时间核验。可以通过以下命令快速确认系统基础信息：

  • lscpu 或 nproc：核对逻辑核心数与 CPU 型号（关注是否限制了单核主频）。
  • free -h 与 df -h：检查可用物理内存、Swap 空间与实际挂载的磁盘分区容量。
  • 磁盘 I/O 评估：使用 fio 测试 4K 随机读写（对数据库和网页响应至关重要），不要仅依赖单一的顺序 dd 写入结果。NVMe 宿主机正常的 4K 随机读写通常在数百 MB/s 以上；若长期低于 50 MB/s，说明宿主机磁盘负载较高。

第二步：网络吞吐与回程路由检查

除了查看商家提供的 Looking Glass，在机器内部也可以结合本地测速与路由追踪工具验证网络质量：

  • 使用 mtr -rwzbc 20 <本地公网IP> 观察从 VPS 返回你本地宽带的每一跳延迟与丢包情况。
  • 测试单线程与多线程下载速率，确认是否存在明显的端口限速（例如标称 1Gbps 带宽但单线程被限制在 50Mbps 以内）。

第三步：基础系统加固（上线前必做）

刚开通的公网 VPS 很快就会遭到自动化扫描器爆破。在部署任何正式业务前，建议完成以下四项基础配置：

  1. 切换为 SSH 密钥登录：在 /etc/ssh/sshd_config 中设置 PasswordAuthentication no，彻底杜绝暴力破解风险。
  2. 启用系统防火墙：使用 ufw 或 firewalld 仅放行必需端口（如 SSH、80、443）。
  3. 开启 BBR 拥塞控制：对于 Linux 4.9+ 内核的 KVM 机器，启用 TCP BBR 可显著提升高延迟或轻度丢包环境下的单线程传输效率。
  4. 配置自动安全更新：Debian/Ubuntu 系统可启用 unattended-upgrades，及时修补高危系统漏洞。
